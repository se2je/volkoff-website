# Т-Касса: подключение рублёвых платежей

Карты РФ (МИР / Visa / MC), СБП, T-Pay, SberPay — через интернет-эквайринг Т-Банка.
Деньги приходят на расчётный счёт ИП в Т-Банке, обычно на следующий рабочий день.

> Ссылки ниже — по памяти: сайты Т-Банка не открылись из среды, где готовилась интеграция
> (они на сертификатах Минцифры). Если ссылка устарела — заходи с https://www.tbank.ru/business/.

## 1. Что сделать в Т-Банке

| Шаг | Где | Что |
|---|---|---|
| 1 | https://www.tbank.ru/business/rko/ | Открыть расчётный счёт ИП (если ещё нет) |
| 2 | https://www.tbank.ru/kassa/ → «Подключить» | Заявка на **интернет-эквайринг**: тип — интернет-магазин, сайт `https://volkoffmvs.com`, способ подключения — **API / свой сайт** |
| 3 | Личный кабинет https://business.tbank.ru → раздел интернет-эквайринга → «Магазины» | Банк заводит магазин и выдаёт **тестовый терминал** (ключ терминала оканчивается на `DEMO`) |
| 4 | Там же, настройки магазина | Подключить **онлайн-кассу** для чеков 54-ФЗ: облачные «Т-Чеки» Т-Банка или свою кассу |
| 5 | Там же | Пройти **обязательные тест-кейсы** на тестовом терминале (список есть в кабинете) |
| 6 | Там же | После тестов банк выдаёт **боевой терминал** → меняем ключи в Vault |

Документация для разработчиков: https://developer.tbank.ru/eacq/

### Перед заявкой: сайт должен пройти модерацию

Банк проверяет сайт. Уже есть: оферта, политика ПДн, согласие, контакты, цены, корзина, условия доставки и возврата, HTTPS.
**Не хватает реквизитов продавца** — их нужно вписать в `apps/web/src/config/site.ts` (`LEGAL`):
ФИО ИП, ИНН, ОГРНИП, адрес. Они подставятся в оферту и политику.

Также проверь, что у ИП есть ОКВЭД **47.91** (торговля через интернет).

## 2. Настройки терминала в кабинете

| Настройка | Значение |
|---|---|
| Тип оплаты | **Одностадийная** (деньги списываются сразу; ждём статус `CONFIRMED`) |
| Уведомления | **По протоколу HTTP**, URL: `https://volkoffmvs.com/api/payments/webhook/tkassa` |
| Success URL / Fail URL | Можно оставить пустыми — сайт передаёт адрес возврата в каждом платеже (страница заказа) |
| Чеки | Включить, налогообложение — как у ИП (обычно УСН «доходы») |

## 3. Ключи → Vault

Путь тот же: **`apps/volkoff_website`**.

| Ключ | Обязательно | Значение |
|---|---|---|
| `TKASSA_TERMINAL_KEY` | да | Ключ терминала (TerminalKey) из кабинета |
| `TKASSA_PASSWORD` | да | Пароль терминала (Password) из кабинета |
| `TKASSA_TAXATION` | нет, по умолчанию `usn_income` | Система налогообложения для чека: `osn`, `usn_income`, `usn_income_outcome`, `esn`, `patent` |
| `TKASSA_VAT` | нет, по умолчанию `none` | Ставка НДС в позициях чека. Для УСН без НДС — `none`. Если ИП платит НДС — значение уточнить у бухгалтера и в документации |
| `TKASSA_SEND_RECEIPT` | нет, по умолчанию `true` | `false`, если к терминалу **не** подключена онлайн-касса |
| `TKASSA_API_URL` | нет | По умолчанию `https://securepay.tinkoff.ru/v2` |

Как только в Vault появятся `TKASSA_TERMINAL_KEY` и `TKASSA_PASSWORD` и прошёл деплой, способ оплаты «карта РФ / СБП»
автоматически идёт через Т-Кассу. Без ключей — через тестовый mock, как сейчас. Остальные способы пока на mock.

## 4. Сертификат Минцифры (обязательно)

API Т-Кассы работает на сертификате Минцифры, которому Node.js по умолчанию не доверяет.
Без него каждая оплата будет падать с `PAYMENT_PROVIDER_UNAVAILABLE` (заказ при этом отменяется, резерв снимается).
Инструкция: [apps/api/certs/README.md](../apps/api/certs/README.md).

## 5. Как проверить на тестовом терминале

1. Положить тестовые ключи в Vault, задеплоить.
2. На сайте: корзина → оформление → «карта РФ / СБП» → «перейти к оплате».
3. Откроется платёжная форма Т-Кассы. Оплатить **тестовой картой** из кабинета тестового терминала.
4. Форма вернёт на страницу заказа. Через несколько секунд (когда придёт уведомление) статус станет «оплачен», на почту уйдёт письмо.
5. Возврат: админка → заказы → статус «отменён» или «возврат» → деньги возвращаются через API Т-Кассы, вещи — на склад.

## Как это устроено в коде

- `apps/api/src/payments/tkassa.ts` — `Init` (создание платежа с чеком 54-ФЗ), подпись `Token`
  (SHA-256 от отсортированных значений корневых параметров + пароль), разбор уведомлений, `Cancel` для возвратов.
- Уведомления: `POST /api/payments/webhook/tkassa`. Подпись проверяется, сумма сверяется с выставленной,
  в ответ — текст `OK`. Повторные уведомления безопасны.
- Ссылка на оплату живёт столько же, сколько резерв товара (30 минут, `RedirectDueDate`).
- Тесты подписи: `npm test --workspace @volkoff/api`.
